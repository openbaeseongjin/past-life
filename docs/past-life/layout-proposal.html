출생 서류 (`birthRecord`) 및 "삶을 시작하기" 버튼 칸 문제 진단 & 기획안

사용자 피드백에서 지적된 "삶을 시작하기 버튼 칸이 전체화면에 맞지 않게 되는 현상"의 근본 원인을 분석하고, 해상도와 창 크기에 상관없이 완벽한 비율과 클릭 편의성을 제공하는 반응형 레이아웃 솔루션을 제안합니다.

🔍 발견된 레이아웃 불일치 원인

  • 버튼 박스 좌측 쏠림: .doc 너비는 최대 760px인데, 하단 버튼 영역 .btns는 max-width: 420px;로 고정되어 왼쪽으로 어색하게 치우침.
  • 노트북 / 1366×768 해상도 스크롤 밀림: 서류 본문에 동갑내기 10명 목록(.peers)과 출생 배경 표가 길게 나열되어, 일반 노트북(세로 768~900px)에서 "삶을 시작하기" 버튼이 화면 아래로 잘려 보임.
  • 대형 화면(FHD/QHD) 수직 비대칭: #screen에 수직 중앙 정렬(flex center)이 없어 대형 화면에서 서류가 상단 천장에 딱 붙고 하단이 텅 빔.
미리보기 모드: 개선안 (After) 화면 규격: 데스크톱 Full HD (1920 × 1080)

✨ 개선안 구현 설계 (적용할 코드 계획)

  • 1. 서류 폭 맞춤형 주 액션 버튼: .doc .btns를 max-width: 100%;로 확장하고, "삶을 시작하기" 버튼을 중앙 정렬 + 금빛 앰버 그라데이션 및 펄스 효과를 부여하여 시각적 완성도와 클릭 직관성 극대화.
  • 2. 뷰포트 맞춤 스마트 수직 정렬: #screen에 display: flex; flex-direction: column; justify-content: center; align-items: center; min-height: 100%; 적용하여 전체화면에서 서류가 황금비율 위치에 안착.
  • 3. 컴팩트 2단 동갑내기 그리드: 동갑내기 목록을 2열 그리드로 정돈하고 서류 패딩을 최적화하여 노트북 768p에서도 스크롤 없이 버튼이 한눈에 들어오도록 핏 조정.
  • 4. 옵션: 플로팅 고정 액션 바 지원: 세로 높이가 매우 협소한 창(600px 이하)에서는 서류 하단에 우아한 반투명 유리 블러 액션 바로 고정.

인게임 메인 HUD (`#app`) 전체화면 핏 & 안전 여백 개선안

게임 플레이 화면에서 좌측 영혼 배지/수치판, 상단 시대의 바람띠, 우측 해시계/두루마리, 하단 구슬실이 화면 크기에 유연하게 반응하도록 정돈합니다.

🔍 HUD 충돌 및 레이아웃 결함 분석

  • 시대의 바람 띠 (`.windbar`): left: calc(var(--left) + 300px); right: calc(var(--right) + 446px);로 좌우가 강제 고정되어, 창 너비가 1024~1200px 구간일 때 너비가 200px대로 줄어들며 텍스트가 잘림.
  • 개선 기획: .windbar를 left: 50%; transform: translateX(-50%); width: min(480px, calc(100vw - 760px)); 형태로 중앙 고정시키고, 공간이 좁아지면 좌측 수치판과 우측 해시계 사이에서 자동 축소/스마트 팝업 모드로 전환.
  • 하단 구슬실과 패: 대형 모니터(1920x1080 이상)에서 너무 화면 끝에 붙어 시선이 분산되지 않도록 max-width: 1400px; margin: 0 auto; 래퍼 컨테이너 적용.

갈림길 & 모닥불 모달 화면 전체화면 핏

인생의 중요한 선택(갈림길 xcard)과 나이대별 모닥불 기억 선택(ccard)이 모니터 비율에 구애받지 않고 중앙에 집중되도록 개선합니다.

🔍 모달 핏 개선안

  • 엠블럼 위치 보정: .emblem이 top: -36px로 카드 밖으로 돌출되어 있어, 뷰포트 높이가 낮은 노트북에서 상단이 브라우저 탭에 가려지는 현상 방지 (상단 패딩 안전마진 확보).
  • 선택지 반응형 너비: 선택지 버튼(.path) 내 글자와 획득 능력치 배지(.pfx)가 줄바꿈되더라도 세로 정렬이 흐트러지지 않도록 Flex-wrap 정밀 조정.

⚡ 3D 모델링 로딩 렉 & 프레임 드랍 원인 정밀 점검 리포트

"진행하면서 모델링 불러오는 게 느려서 렉 같은 게 걸리는 것 같다"는 점검 요청에 대해, 코드베이스와 브라우저 렌더링 파이프라인을 추적하여 실제 렉의 4대 원인과 최적화 해법을 도출했습니다.

1

대용량 GLB 에셋 동시 다운로드 병목

탄생 직후 마을 1개를 짓기 위해 10MB 이상의 3D 파일이 한꺼번에 병렬 요청됩니다.

• eastasia_korea.glb: 4.71 MB
• props_eastasia.glb: 3.70 MB
• villagers_eastasia.glb: 1.80 MB
• anims.glb: 0.70 MB + 1K 텍스처들
👉 총합 약 12~15 MB 네트워크 소요
해결책: 사전 로딩 (Preloading)
시작 화면 또는 탄생 인트로(별하늘/지도 연출 3~5초) 진행 중에 백그라운드에서 해당 세트 GLB를 미리 fetch하여 캐싱해 둡니다.
2

메인 스레드 지오메트리 변환 동기 렉

GLB 다운로드가 끝난 직후 자바스크립트 메인 스레드가 13만 개 이상의 버텍스를 동기 루프로 변환 및 병합합니다.

• buildKit(): floatGeoOf 13만 정점 for문
• buildGrass(): 16만 6천개 풀 인스턴스 행렬 계산
• buildHedges(): 수천 개 노멀 계산
👉 메인 JS 스레드 600~1,200ms 완전 프리징
해결책: 타임 슬라이싱 (Time-slicing)
빌드 함수들 사이에 await nextTask()를 촘촘히 분할 배치하여 브라우저가 프레임을 계속 그릴 수 있도록 양보합니다.
3

"삶을 시작하기" 클릭 시점과 무대 준비 불일치

사용자가 출생 서류를 1~2초 만에 빨리 읽고 "삶을 시작하기"를 누르면, 무대가 아직 완성되지 않은 상태에서 전환 애니메이션이 시작됩니다.

• record 완료 즉시 ui.mapZoom() 실행
• 뒤늦게 Three.js 지오메트리 빌드가 겹치면서
• 지도 확대 애니메이션이 심하게 끊김!
해결책: 준비 상태 스무딩 (Ready Smoothing)
village.whenReady()가 끝날 때까지 "마을을 짓는 중..." 블러 페이드를 부드럽게 유지하거나, 준비 직후 매끄럽게 카메라를 넘깁니다.
4

Three.js 동기 셰이더 컴파일 지연

씬이 화면에 처음 렌더링될 때 수십 개의 PBR 셰이더가 GPU 드라이버 레벨에서 동기 컴파일되며 150~300ms 멈춤이 발생합니다.

• renderer.compile(scene, camera)가 돌지만
• 조명/포스트프로세싱/안개 셰이더가 첫 프레임에 재컴파일
👉 렌더링 시작 순간 프레임 드랍 체감
해결책: 셰이더 웜업 & 텍스처 압축
첫 씬 로드 시 오프스크린 1프레임 프리컴파일 및 불필요한 고해상도 텍스처를 512px로 최적화 유지.

최적화 적용 시 예상 체감 효과

✓ 출생 서류에서 "삶을 시작하기"를 눌렀을 때 무대로 넘어가는 렉(프리징) 100% 해소
✓ 탄생 인트로 동안 백그라운드 프리로딩으로 3D 마을 체감 로딩 시간 3초 ➔ 0.3초 미만 즉시 전환
✓ 지도 확대(mapZoom) 애니메이션 60 fps 매끄러운 진행
